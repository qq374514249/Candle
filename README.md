# 蜡烛图买卖信号 → Telegram

每个交易日**盘前 / 盘中 / 盘后**三次，把 8 只科技巨头的买卖时机推到你的 Telegram。
跑在 GitHub Actions 上，免费、不需要服务器、不需要开着电脑。

---

## 策略

盯 **NVDA · TSLA · AAPL · MSFT · AMD · META · GOOGL · AMZN**，日线，多空都做。

| | 规则 |
|---|---|
| **买入信号**<br>G3 影线不对称 | `x = ((min(开,收) − 低) − (高 − max(开,收))) / (高 − 低)`<br>`r` = x 在最近 **60** 个交易日里的分位<br>`r ≥ 0.80` → 次日开盘**做多**　　`r ≤ 0.20` → 次日开盘**做空** |
| **卖出信号**<br>G8 跳空 | `y = (今开 − 昨收) / 昨收`<br>`r` = y 在最近 **60** 个交易日里的分位<br>持多仓且 `r ≤ 0.20` → 次日开盘**平仓**<br>持空仓且 `r ≥ 0.80` → 次日开盘**平仓** |
| **安全阀** | 任何持仓浮亏到 **8%** 立即离场 |

回测（2024-08-29 → 2026-08-28，501 根日线，单边成本 0.05%）：
8 只股票平均 **1.55x**，8/8 全部盈利，切成前后各一年后仍是 7/8 和 7/8，
最大回撤 −29.8%，仓位只在场 59% 的时间，胜率 51.2%。

> ⚠️ **同期买入持有是 1.75x。** 而且噪声对照显示：把指标换成随机信号跑同样规模的搜索，
> 有约 15% 的概率能造出同样漂亮的结果。这是一套**监控工具**，不是投资建议。

## 四条消息分别是什么

| 时段 | 美东时间 | 内容 |
|---|---|---|
| 🔔 **盘前** | 08:45 | **今天开盘要做的事**（昨收算出的挂单）+ 持仓与止损价 + 今日开盘的平仓触发价 |
| 📊 **盘中** | 12:30 | **止损监控**：哪只逼近或已触及 8% 止损 + 实时浮盈亏 |
| 🌙 **盘后** | 16:30 | **明天开盘要做的事** + 8 只股票今日信号读数 + 明日开盘的平仓触发价 |
| 🌤️ **休市** | 10:30 | 周末与美股假日照常播报：**下一个交易日开盘要做的事** + 按最新收盘价的持仓浮盈亏 + 开盘平仓触发价 + 信号读数 |

休市日一天只发一条，交易日不会发休市那条 —— 四条 cron 在夏令时/冬令时下都已验证过不重不漏。

### 关于「开盘平仓触发价」

卖出信号 G8 只用到**今开**和**昨收**两个数，所以它是唯一能提前折算成一个具体价位的信号。
脚本会算出下一个交易日的开盘价落在什么位置会触发平仓，直接给你报价：

```
TSLA  空头 → 开盘 ≥ 351.19 则发出平仓信号
AMZN  多头 → 开盘 ≤ 265.23 则发出平仓信号
```

注意措辞是「**发出**平仓信号」：按策略规则，在第 N 天开盘触发的信号，是在**第 N+1 天开盘**执行的。
价位已按分取整并各向外让了一档，报价碰到就一定在触发区间内。

买入信号 G3 要用到整根 K 线的形状（开高低收都要），没法压成一个价位，所以只给读数不给触发价。

## 部署步骤

### 1. 建 Telegram 机器人，拿到 token

1. 在 Telegram 里搜 **@BotFather**，发 `/newbot`
2. 按提示起名字（随便），最后拿到一串形如 `8123456789:AAF...` 的 **token**
3. 搜到你刚建的机器人，点 **Start** 给它发一句话（不发它没法给你发消息）

### 2. 拿到你的 chat id

浏览器打开（把 `<TOKEN>` 换成上一步的 token）：

```
https://api.telegram.org/bot<TOKEN>/getUpdates
```

在返回的 JSON 里找 `"chat":{"id":123456789` —— 那串数字就是 **chat id**。
> 想发到群里就把机器人拉进群、在群里发一句话再打开这个链接，群的 id 是负数（如 `-1001234567890`）。

### 3. 把代码放进仓库

在 GitHub 新建一个仓库（**Private 即可**），放入这两个文件：

```
你的仓库/
├── scripts/candle-alert.mjs
└── .github/workflows/candle-alert.yml
```

### 4. 填入密钥

仓库页面 → **Settings** → 左栏 **Secrets and variables** → **Actions** → **New repository secret**，
建两条：

| Name | Secret |
|---|---|
| `TELEGRAM_BOT_TOKEN` | 第 1 步的 token |
| `TELEGRAM_CHAT_ID` | 第 2 步的数字 |

### 4b. 建议：加一个 Twelve Data 免费 key

Yahoo 没有官方 API，是靠爬它网页用的接口，而且**限流是按 IP 算的** —— GitHub 的服务器 IP 段被
全世界的脚本共用，所以经常 429。Twelve Data 是正经 API，**限流按 key 算**，你自己一天只用 32 次，
额度是 800，根本用不完。

1. 去 [twelvedata.com](https://twelvedata.com/pricing) 注册（免费，不要信用卡），拿 API key
2. 按上面的方法再加一条 Secret：

| Name | Secret |
|---|---|
| `TWELVEDATA_API_KEY` | 你的 key |

加了之后脚本会**自动把 Twelve Data 当主源、Yahoo 当兜底**，不用改任何代码。
不加也能跑，只是偶尔会有股票取不到数。

> 两个源的数据经过验证是等价的：同样的 8 只股票，解析后逐根 K 线 0 差异，
> 回测终值与持仓状态完全相同 —— **换源不会改变任何信号**。

### 5. 开启并测试

1. 仓库 → **Actions** 标签页 → 如果提示 `I understand my workflows, enable them`，点它
2. 左栏点 **蜡烛图信号提醒** → 右侧 **Run workflow**
3. `session` 选 **POST**（或 **CLOSED** 看休市版），点绿色 **Run workflow**
4. 十几秒后 Telegram 应该收到消息 ✅

之后就自动了，每个交易日三次。

## 收不到消息怎么查

| 现象 | 原因与处理 |
|---|---|
| 手动 Run 也没消息 | 没先给机器人发过 Start；或 token / chat id 填错。把 `dry_run` 勾上再跑一次，日志里能看到消息全文和错误 |
| 日志报 **HTTP 429** | Yahoo 按 IP 限流，GitHub 的服务器 IP 经常被限。**最有效的解法是加一个 Twelve Data 免费 key**（见步骤 4b），限流就变成按 key 算，不再受影响 |
| 日志显示「TwelveData 整批失败（配置错误）」 | key 填错或过期。脚本会立刻切回 Yahoo，不会空转 |
| 消息末尾有「⚠️ 取数失败」 | 部分股票这次没取到，其余照常。下一次运行会自己恢复，不用管 |
| 自动的没触发 | 仓库连续 60 天没提交，GitHub 会自动停用 schedule —— 进 Actions 页面点 **Enable workflow** 即可 |
| 时间晚了十几分钟 | GitHub cron 在高峰期会排队，属正常。窗口留了近 1 小时余量 |
| 任务跑了 5～6 分钟 | 正常。取数时被限流会一路退避重试，比直接失败好 |

## 可调项

在 `.github/workflows/candle-alert.yml` 的 `env:` 里改：

- `ALLOW_SHORT: '0'` —— 只发做多信号，看空时只提示清仓不提示做空
- `QUIET_INTRADAY: '1'` —— 盘中一切正常时不发消息，只在逼近/触及止损时才响
- `RETRY_SCALE: '2'` —— 把两轮重试的等待从 30s/60s 拉长到 60s/120s，限流特别严重时用
- `DATA_SOURCE` —— `auto`（默认，配了 key 就用 Twelve Data 打头）/ `yahoo` / `twelvedata` 写死主源

在 `scripts/candle-alert.mjs` 顶部改：

- `TICKERS` —— 换股票（注意：这套规则只在这 8 只科技股上验证过）
- `NEAR_STOP` —— 盘中「逼近止损」的提醒阈值，默认浮亏 6%
- `WIN` / `HI` / `LO` / `STOP` —— 策略参数，**改了就不是回测过的那套了**

## 关于状态

脚本**不存任何状态**。每次运行都从两年历史完整重放一遍，推导出当前该持有什么。
所以：断几天再跑会自动回到正确状态，不需要数据库，也不会因为漏跑一次就错乱。

代价是它跟踪的是**策略应该持有什么**，不是你账户里**实际持有什么**。真下单的话，
以盘前那条消息为准手动执行，让两边保持一致。
